# 알림 기능과 UI 고도화 설계

작성일: 2026-07-31
적용 대상: `bgms-mobile-app`

## 1. 배경과 제약

로드맵 `다음 작업 후보 5`에 "알림 기능 준비: 즐겨찾기 기반 전적 갱신 알림, 시즌 변경 알림,
로컬/서버 푸시 경계를 정한다"가 남아 있다. 이 문서가 그 경계를 확정한다.

확인한 제약은 세 가지다.

- 푸시 인프라가 전혀 없다. FCM 의존성, Supabase Edge Functions, 발송 스케줄러가 모두 없다.
- 운영 서버(`bgms.kr`)가 현재 402 `DEPLOYMENT_DISABLED` 상태다. 서버 의존 기능은 검증할 수 없다.
- 1차 목표는 Android/iOS 내부 테스트 진입이다. APNs 인증서와 스토어 푸시 권한 심사를 끼우면
  일정이 밀린다.

## 2. 범위 결정

이번 작업은 서버를 추가하지 않고 앱 안에서 완결한다.

포함:
- 인앱 알림 센터. 알림 목록, 읽음 처리, 미읽음 배지.
- 즐겨찾기 플레이어의 전적 변화 감지. 새 매치, 티어 변동, 시즌 변경.
- OS 로컬 알림. 앱이 백그라운드일 때 감지 결과를 기기 알림으로 표시.
- 알림 설정. 종류별 on/off, 확인 주기.

제외 (별도 사이클):
- FCM/APNs 서버 푸시. 서버 복구와 인프라 구축이 선행 조건이다.
- 알림 히스토리 서버 동기화. 기기 로컬에만 저장한다.

## 3. 감지 방식

서버에 신규 API를 만들지 않고 기존 `/api/pubg/player` 응답을 스냅샷으로 저장해 비교한다.

```text
이전 스냅샷(로컬)  vs  현재 응답(API)  ->  차이를 알림 이벤트로 변환
```

비교 대상과 알림 종류는 다음과 같다.

| 종류 | 감지 기준 | 문구 예시 |
| --- | --- | --- |
| 새 매치 | `recentMatches` 최상단 matchId가 바뀜 | "새 매치 3건이 기록되었습니다" |
| 티어 변동 | `tier` 또는 `subTier` 변화 | "Platinum 3에서 Diamond 5로 올랐습니다" |
| 시즌 변경 | `seasonId` 변화 | "새 시즌이 시작되었습니다" |

감지 로직은 순수 함수로 둔다. 입력은 이전 스냅샷과 현재 프로필, 출력은 알림 이벤트 목록이다.
네트워크와 저장소에 의존하지 않으므로 단위 테스트가 쉽고, 나중에 서버 푸시로 옮길 때
서버 쪽으로 그대로 이동할 수 있다.

## 4. 컴포넌트 구조

```text
lib/features/notifications/
  notification_models.dart      알림 이벤트, 종류, 스냅샷 모델
  notification_detector.dart    스냅샷 비교 순수 함수
  notification_store.dart       알림 목록과 스냅샷 로컬 저장 (SharedPreferences)
  notification_service.dart     감지 실행과 OS 알림 표시 조율
  notification_settings.dart    알림 설정 모델과 저장
  notifications_screen.dart     알림 센터 화면
```

각 단위의 책임은 다음과 같다.

- `notification_detector.dart`: 입출력이 명확한 순수 함수. 외부 의존 없음.
- `notification_store.dart`: 직렬화와 영속화만 담당. 감지 로직을 모른다.
- `notification_service.dart`: 저장소에서 스냅샷을 읽고, API를 호출하고, 감지 함수를 돌리고,
  결과를 저장하고 OS 알림을 띄운다. 조율만 하고 판단 로직은 갖지 않는다.
- `notifications_screen.dart`: 표시와 사용자 조작만 담당.

## 5. 백그라운드 실행

`flutter_local_notifications`로 OS 알림을 띄운다. 감지 실행 시점은 두 가지다.

- 앱 포그라운드 진입 시. 마지막 확인 시각이 설정된 주기보다 오래되었으면 즉시 확인한다.
- 앱 사용 중 즐겨찾기 화면 진입 시.

`workmanager` 같은 주기적 백그라운드 실행은 이번 범위에서 제외한다. iOS는
백그라운드 fetch 시점을 OS가 결정해 동작이 불규칙하고, 즐겨찾기 인원만큼 API를 호출하면
PUBG API 호출 한도에 부담이 된다. 앱을 열 때 확인하는 방식으로 시작하고, 실사용 데이터를
본 뒤 필요하면 서버 푸시로 넘어간다.

이 선택의 결과로 알림은 즉시성이 없다. 설정 화면에 이 동작 방식을 문구로 알린다.

## 6. 저장 구조

`SharedPreferences`에 JSON으로 저장한다. 기존 `LocalPlayerStore`와 같은 방식이다.

| 키 | 내용 |
| --- | --- |
| `bgms.notifications.items` | 알림 목록. 최근 50건까지 유지 |
| `bgms.notifications.snapshots` | 플레이어별 마지막 스냅샷 |
| `bgms.notifications.settings` | 종류별 on/off, 확인 주기 |
| `bgms.notifications.lastCheck` | 마지막 확인 시각 |

알림 목록이 50건을 넘으면 오래된 항목을 버린다. 무한 증가를 막고 저장 용량을 예측 가능하게 한다.

## 7. 화면 설계

### 7.1 알림 센터

진입 경로는 홈 헤더의 벨 아이콘이다. 탭을 하나 더 만들지 않는다. 하단 탭이 이미 6개로
포화 상태이고, 알림은 상시 탐색 대상이 아니라 확인 후 벗어나는 화면이다.

미읽음이 있으면 벨 아이콘에 카운트 배지를 겹친다. 배지 크기는 고정해 아이콘 정렬이
흔들리지 않게 한다.

구성:
- 알림 목록. 종류 아이콘, 문구, 상대 시각, 미읽음 점
- 항목 탭 시 해당 플레이어 전적으로 이동하고 읽음 처리
- 전체 읽음 처리, 전체 삭제
- 빈 상태는 기존 `InfoPanel`을 쓴다

### 7.2 알림 설정

마이 탭에 배치한다. 현재 마이 화면의 "알림, 동기화 설정은 서버 인증 연결 후 활성화됩니다"
문구를 실제 설정으로 교체한다.

구성:
- 종류별 스위치: 새 매치, 티어 변동, 시즌 변경
- 확인 주기 선택: 앱 실행 시마다, 1시간, 6시간, 하루
- OS 알림 권한 상태 표시와 권한 요청 버튼

## 8. UI 고도화

알림과 별개로 로드맵에 남은 UI 과제를 함께 처리한다.

홈과 전적 탭이 거의 같은 검색 화면이 된 문제를 해결한다. 홈은 알림 센터 진입, 즐겨찾기
현황, 최근 활동을 앞세운 대시보드로 두고, 검색은 compact 입력 한 줄로 축소한다. 전적 탭은
검색과 분석 진입을 유지한다. 알림 센터가 홈에 붙으면서 홈에 고유한 역할이 생기므로
이 분리가 자연스러워진다.

`fontSize` 하드코딩 46곳을 `textTheme` 기반으로 정리한다. 접근성 폰트 배율에 대응하고
화면 간 타이포 위계를 통일한다.

## 9. 오류 처리

감지 과정의 실패는 조용히 넘긴다. 알림은 보조 기능이므로 실패가 주 화면 흐름을 막아서는
안 된다. 실패는 `AppObservability.logger`에 기록하고 다음 확인 시점에 다시 시도한다.

`ApiException.isRetryable`이 false인 실패(닉네임 삭제 등)가 반복되면 해당 플레이어의
감지를 건너뛴다. 존재하지 않는 닉네임에 매번 API를 호출하는 낭비를 막는다.

OS 알림 권한이 없으면 인앱 알림 센터만 동작한다. 권한 거부가 기능 전체를 막지 않는다.

## 10. 테스트 범위

- `notification_detector`: 새 매치, 티어 상승, 티어 하락, 시즌 변경, 변화 없음, 첫 스냅샷
- `notification_store`: 직렬화 왕복, 50건 상한, 읽음 처리
- `notification_settings`: 기본값, 종류별 on/off 반영
- 알림 센터 화면: 목록 렌더링, 빈 상태, 읽음 처리, 배지 카운트
- 감지 서비스: 설정이 off면 해당 종류를 만들지 않음, 재시도 불가 오류 시 건너뜀

OS 알림 표시는 플랫폼 채널이라 단위 테스트 대상에서 제외한다. 대신 표시 호출을 인터페이스로
분리해 fake로 검증한다.
