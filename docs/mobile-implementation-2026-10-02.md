## 2단계 기존 API와 공개 DB 연결

| 기능 | 앱에서 제공하는 범위 | 데이터와 인증 |
|---|---|---|
| 저장 경기 이력 | 페이지 조회, 경기 유형 선택, 더 보기, 상세 이동 | `/api/pubg/player/matches` |
| 플레이어 비교 | 두 닉네임·플랫폼·경기 유형 선택, 기본·전술 지표 및 비교 가능 여부 | `/api/pubg/battle` |
| 상대 기록 | 만난 상대 목록, 경기별 수집, 상대 프로필 조회, 관심 추적 등록 | `/api/pubg/encounters`, 로그인 |
| 관심 추적 | 제재 상태·확인 시각·변화 표시, 확인 후 항목 삭제 | `/api/pubg/ban-watch`, 로그인 |
| 무기 숙련도 | 명시적 조회와 오류·빈 상태 | `/api/pubg/player/weapon-mastery` |
| 고객센터 | 공개 FAQ, 본인 문의 목록·상세, 일반 문의 작성, 답변·추가 메시지, 기존 증빙 열람 | `/api/support/*`, 개인 데이터는 Bearer |
| 게시판 답글 | 부모 댓글을 지정한 작성과 답글 표시 | 모바일 댓글 API의 `parent_id` |
| 무기 도감·비교 | 검색, 두 무기 비교, 파츠 선택과 반동·재장전 효과 | 공개 `weapons`, `attachments` 읽기 |
| 가방·트렁크 | 조끼·가방 레벨, 차량 선택, 아이템 수량과 무게 합계·초과 표시 | 공개 아이템·차량 테이블 |
| 총기 메타 | 일반·경쟁·전체, 패치·총기 분류, 패치 전후 지표·표본 안내 | `/api/pubg/meta` |
| 핫드랍 | 맵 선택과 수집된 착지 표본 표시 | `/api/pubg/hotdrop` |
| 경기 2D 리플레이 | 경기 상세에서 조회, 선택 선수의 이동 기록·자기장·교전 타임라인 | `/api/pubg/telemetry?mode=lite`와 검증된 HTTPS 다운로드 |

도구는 홈의 `BGMS 도구 보기`와 마이에서 열 수 있다. 조회 실패를 정상 기록으로 대체하지 않으며 전적·도구의 수집 표본을 전체 PUBG 통계라고 설명하지 않는다. 리플레이는 서버 보존 기간·지원 맵·기록 존재 여부에 따라 이용할 수 있다.

문의 메시지의 중복 방지 키는 서버 계약대로 `Idempotency-Key` 헤더에 넣고 재시도에는 같은 키를 사용한다. 개인 문의와 초안은 계정 변경 시 이전 계정 내용을 재사용하지 않도록 처리한다. 증빙 열람은 매번 새 서명 URL을 요청한다. 신규 사진 첨부와 개인정보 문의는 아직 앱에서 제공하지 않는다.

지도 확대 시 보이는 영역의 고해상도 타일을 추가 조회하고 밀집 마커를 묶는다. 2D 리플레이는 위치 기록 사이의 실제 이동을 보증하지 않으며 긴 기록 공백은 선으로 잇지 않는다. 3D 재생과 자기장 연습은 별도 단계다.

## 사용자 지정 계정과 경기 누락 진단

사용자가 지정한 `KangHeeSung_`와 `MiaeQ_Q`를 Steam에서 조회했다. 각 계정의 최근 20경기 요청에 요약 20개가 모두 반환됐고 `missingMatchIds`와 `matchType=unavailable` 항목은 없었다. 서버 응답의 선수 이름·계정 ID도 각 요청 선수와 일치했다. 이후 실기기 테스트 대상은 이 두 계정으로 교체했다.

앞서 사용한 TGLTN은 공개 샘플 닉네임이었다. 확인 당시 프로필 동기화는 2026-07-30, 최근 20경기 요약은 1개 반환·19개 누락이었다. 반환된 1개도 `unavailable` placeholder여서 정상 경기 기록으로 사용할 수 없었다. 앱은 요약이 없는 모든 경우를 `분석 대기`로 표현했지만 이 API 경로는 기본 기록 부재·조회 실패를 작업 큐 대기로 보증하지 않는다. 문구를 `경기 정보 없음`으로 바로잡고 실제 분석 대기와 구분했다. 프로필 캐시가 갱신되지 않은 운영 원인과 과거 경기 재수집 가능 여부는 별도 서버 확인이 필요하다.
