# BGMS 모바일 앱 병합 점검 및 개선 보고

점검일: 2026-10-01
대상: `codex/mobile-ui-and-suggestions` → `main`, [PR 1](https://github.com/ka6865/bmgs-app/pull/1)

현재 브랜치의 기존 37개 커밋과 미커밋 앱 변경을 검토했다. 메인은 현재 브랜치의 조상이며 상충하는 메인 커밋은 없었다. 코드 리뷰에서 발견한 데이터 표시 오류와 UI 문제를 수정한 뒤 전체 테스트와 정적 분석을 기준으로 병합한다. 로컬 작업 메모와 별도 백업 워크트리는 보존한다.

## 확인 범위와 한계

- Flutter 3.44.4 / Dart 3.12.2, `flutter pub get` 완료.
- 앱 코드, 모바일 클라이언트와 기존 웹 API 계약, 회귀 테스트 및 iOS 설정 파일을 점검했다.
- 운영 API 확인 시각은 2026-10-01 21:41~21:43 KST다. 서버 데이터 개수는 그 시각의 응답 기준이다.
- 맥북 용량 제약에 따라 시뮬레이터, SDK 추가 다운로드, 네이티브 release 빌드 및 통합 워크스루는 이번 최종 점검에서 실행하지 않았다.
- 320/360 logical px 및 1.5배 글꼴의 매치 카드 레이아웃은 실제 기기 대신 Flutter 위젯 테스트로 확인했다. 다른 화면의 큰 글꼴, TalkBack/VoiceOver, 스플래시 전환은 실기기 검증이 남아 있다.
- 로그인, 게시글·댓글 실제 작성, 계정 삭제, 유료 AI 호출은 실행하지 않았다. 앱·서버 계약 확인과 모의 응답 테스트 결과를 실서비스 성공으로 간주하지 않는다.

## 이번에 수정한 사항

1. 기본 전적만 제공하는 `analysisAvailability: basic_only` 응답을 “분석 완료”와 0점 전술 분석으로 표시하지 않게 했다. 기본 전적은 유지하고 분석 불가 상태를 표시한다.
2. AI NDJSON의 `error`와 `done.valid: false`를 실패로 처리하며, final 뒤 실패 신호도 확인한다. 새 경기 목록으로 갱신되면 이전 AI 결과를 지우고 수동 요청을 기다린다.
3. 매치 요약 API 장애가 성공한 시즌 전적까지 숨기지 않게 했다. 프로필과 매치 ID를 보존하고 부분 오류를 안내하며, 장애 시 상세 자동 호출을 건너뛴다.
4. 플레이어·플랫폼 변경 시 즐겨찾기를 다시 읽으며 이전 대상의 비동기 결과를 새 화면에 적용하지 않게 했다.
5. 알림이 항상 첫 5명만 확인하던 문제를 기존 스냅샷의 확인 시각으로 순환 처리했다. OS 설정에서 바뀐 알림 권한도 다시 읽는다.
6. 댓글 작성 후 상세 재조회와 재시도에 서버의 `refresh=1` 계약을 사용한다. 화면을 떠난 뒤 댓글 완료 콜백의 상태 갱신도 방지한다.
7. 매치 카드가 좁은 화면·큰 글꼴에서 넘치는 문제를 재현하고 킬·딜량을 아래 행에 배치했다. 하단 탭 비선택 라벨·아이콘의 대비를 높였다.
8. 홈 배너를 실제 제공하는 전술 지도 기능에 맞는 문구로 수정했다.
9. iOS 에셋 설정의 잘못된 boolean 값을 복원하고 Android 12 시작 후 배경도 다크 색상으로 통일했다. 변경된 화면과 맞지 않던 통합 테스트의 제목·버튼 찾기를 수정했다.
10. AI 실행 콜백이 Future를 반환해 발생하던 Flutter setState assertion을 동기 상태 갱신으로 수정했다.
11. 상자깡 반복 glow 때문에 무작위로 끝나지 않던 테스트를 카드 공개 시간만 진행하도록 바꾸고 10개 결과 카드도 검증한다.

## 2026-10-02 추가 실기기 검증

10월 1일 점검 변경은 PR 1로 `main`에 병합됐다. 아래는 이후 연결한 실기기에서 추가로 확인한 결과이며, 위의 10월 1일 미검증 기록을 소급해서 바꾸지 않는다.

- 환경: iPhone 17 / iOS 27.2 beta, macOS 26.5.1 / Xcode 26.6, Flutter 3.44.4 / Dart 3.12.2.
- 사용자가 Xcode의 iOS 지원 구성요소를 설치하고 아이폰에서 개발자 앱을 신뢰한 뒤, profile 빌드·서명·설치·실행에 성공했다. macOS 전체 업데이트나 시뮬레이터 실행은 하지 않았다.
- 실기기 워크스루 1개 통과: 홈·전적·랭킹·지도·게시판·마이 6개 탭, `TGLTN` 검색, 전적 스크롤. 현재 실행의 캡처 10개를 `screenshots/01_home.png`~`10_stats_matches.png`에 저장했다. 캡처는 Git에 포함하지 않는다.
- 최초 자동 검색 실패는 profile 모드의 테스트 입력 client ID 문제였다. 테스트의 `TestTextInput`을 등록·해제하도록 수정한 뒤 통과했다. 실제 iOS 키보드, 한글 조합, 키보드가 입력창을 가리는지는 이 방식으로 검증하지 않았다.
- 스크린샷 표면 변환은 테스트 시작 시 한 번만 실행하도록 수정했다. iOS에서는 no-op이며, 이 코드 검토가 Android 실기기 검증을 의미하지 않는다.
- 변경 후 `flutter test --concurrency=2`: 225개 통과. `dart analyze`: No issues found. 추가 코드 리뷰에서 병합 차단 오류는 발견되지 않았다.
- 일반 실행용 `lib/main.dart`와 운영 API·Supabase 공개 설정으로 iOS release 빌드, `codesign --verify --deep --strict`, 실기기 설치 및 실행에 성공했다. Mac 디버거 없이 실행하는 개발용 서명 빌드이며, App Store archive·TestFlight 검증과는 별개다.

Android 실기기와 양 플랫폼의 스토어 배포 산출물 검증도 남아 있다. 설치한 iOS 개발용 프로비저닝은 2026-10-09 00:22:17 KST에 만료되므로 이후에는 재서명 및 재설치가 필요하다.
